## DR-001: 本サイクルのスコープ選択

- **ステップ**: セットアップ（サイクル方針決定）
- **日時**: 2026-06-30

### 背景

前サイクル v3.0.0-alpha.7（Phase 6: doctor v1 + reflect + status）完了後、新規サイクルのスコープを決める必要があった。Epic #736（v3 リニューアル Phase 4–7）の軌道上、次の候補として (a) alpha.7 で defer した doctor `[phase]`/`[trace]` の必須 follow-up（#741）、(b) Phase 7 本流化、(c) その他 backlog が存在した。

### 選択肢

| # | 選択肢 | メリット | デメリット |
|---|--------|---------|-----------|
| 1 | #741 doctor `[phase]`/`[trace]` 拡張 | alpha.7 の必須 follow-up を解消し Phase 6 を真に完了 / 受け入れ基準が明確 / 小〜中規模 | 本流化（Phase 7）は次サイクルに持ち越し |
| 2 | #736 Phase 7 本流化 | `/aidlc` = v3 を実現する大型マイルストーン | doctor 未完（phase/trace defer）のまま本流化することになり前提が不完全 / 大型サイクル |
| 3 | その他 backlog（#740 等） | 個別 footgun の解消 | Epic 軌道から外れ、Phase 6 の歯抜けが残る |

### 決定

**選択肢 1（#741 doctor `[phase]`/`[trace]` 拡張）** を採用

### トレードオフと判断根拠

- **得たもの**: Phase 6 の必須 follow-up を解消し doctor を完全診断（11 領域）化。Phase 7 本流化の前提（doctor 完成）を整える。
- **犠牲にしたもの**: Phase 7（本流化）の着手は次サイクル以降に先送り。
- **判断根拠**: #741 はラベル上も alpha.8 に紐付き、Epic #736 で「Phase 6 完了 = v3 単独フルサイクル」の歯抜けを埋める必須項目。本流化（Phase 7）の前に doctor を完成させるのが軌道として自然と判断した。

## DR-002: サイクルバージョンの選択

- **ステップ**: セットアップ（サイクルバージョン決定）
- **日時**: 2026-06-30

### 背景

`suggest-version.sh` は alpha プレリリース命名を解さず `v2.6.7 / v2.7.0 / v3.0.0` を提案したが、直近サイクルは `v3.0.0-alpha.7` であり、#741 のラベルも `[v3.0.0-alpha.8]` を指していた。

### 選択肢

| # | 選択肢 | メリット | デメリット |
|---|--------|---------|-----------|
| 1 | v3.0.0-alpha.8 | alpha プレリリース系列の継続として自然 / #741 ラベル・Epic 進行と整合 | - |
| 2 | v3.0.0（RC/GA） | 本リリース化 | 本流化（Phase 7）未完で RC/GA は時期尚早 |

### 決定

**選択肢 1（v3.0.0-alpha.8）** を採用

### トレードオフと判断根拠

- **得たもの**: alpha プレリリース系列の一貫性と #741・Epic #736 との整合。
- **犠牲にしたもの**: なし（本リリース化は Phase 7 完了後が適切）。
- **判断根拠**: doctor follow-up は alpha 段階の作業であり、RC/GA は本流化完了後とするのが Epic ロードマップに整合する。
