## 実装方針

### Phase 1: 設計

#### 修正対象 3 件の現状

| 行 | 文脈 | 既存記法 | 違反内容 |
|----|------|---------|---------|
| 121 | 「`内容` 列のパス記法（規約）」セクションの例示 | カンマ + 半角スペースを inline code span として記載 | code span 内に先頭/末尾スペースが含まれる |
| 122 | 「Round 1〜3 抽出」手順内の区切り期待値 | 同上（区切りパターンを code span として記載） | 同上 |
| 283 | review-summary 列定義テーブルの「内容」列ルール | 複数パス区切りを code span として記載 | 同上 |

3 件いずれも「複数パスを区切るカンマ + 半角スペース」という規約説明部分で、意図的に code span 内へ
区切り文字 + 半角スペースを入れているのが原因。

#### 書き換え方針（案 1 / 最小修正 + 規約意図維持）

書き換えの基本パターン:

- **パスのみをコード span 化**し、区切り文字（`,`）と半角スペースは平文で記述する
- 区切り文字をコード span 化しない（区切り文字を独立コード span にすると抽出側の正規表現
  ``` `([^`]+)` ``` が区切り文字も抽出してしまい、新領域判定 / パス正規化に副作用を生むため）
- 規約説明文は「backtick で囲んだパスを平文の `,` + 半角スペースで区切る」と再表現する

#### 影響範囲確認

- review-summary 抽出側の正規表現 ``` `([^`]+)` ``` は**非変更**。区切り文字をコード span 化しない
  方針により**副作用なし**
- 他ファイル（`steps/*` / `guides/*` / 各スキル SKILL.md）の MD038 違反は本 Unit のスコープ外

#### テスト設計

本 Unit はドキュメント記法のみの変更のため、追加の自動テストは設けない。

  `review-flow.md` 全体の markdownlint を pass させる
