# Unit: CycleResolver 明示指定優先の回帰テスト（T6）

## 概要

v3 の cycle 解決入口が `state.json` の `current_cycle`（明示指定）を最優先し、git 履歴・周辺ファイル名・ディレクトリ走査順に影響されないことを固定する回帰テストを追加する。v3 本体は既に明示指定一本化済み（gitlog 推定ロジックなし / RFC DG-6）のため、本 Unit はその仕様を回帰テストとして固定し、#733 P4 クラスの再発を防止する。

## 含まれるユーザーストーリー

- ストーリー 4: CycleResolver 明示指定優先の回帰テスト（T6）

## 責務

- `skills/aidlc-v3/scripts/tests/` への cycle 解決回帰テスト追加（新規 `test-cycle-resolution.sh` または既存 `test-state-scripts.sh` への追加）
- 「`current_cycle` 設定時はその値が解決される」検証
- 「git 履歴・周辺ファイル名が `current_cycle` と異なっても解決結果が影響されない」検証（gitlog 推定非依存）
- `current_cycle` 未設定/欠損時の既存仕様どおりの振る舞い（拒否 or 明示エラー）の確認

## 境界

- **扱わない**: framework 側（`skills/aidlc/`）の CycleResolver 修正（#733 P4 で v2.6.6 を返した実体は framework 側ツールの可能性が高いが、本サイクル GA スコープ外 / Intent 除外事項）
- **扱わない**: v3 cycle 解決ロジックの新規実装・変更（既存仕様の回帰テスト固定のみ。プロダクションコード変更が不要なら追加しない）
- **扱わない**: 共有 parser / CI ガード（Unit 001 / 002）

## 依存関係

### 依存する Unit

- なし（cycle 解決は frontmatter parser 集約とは独立。Unit 001/002 と並行実装可能）

### 外部依存

- bash、jq、git、mktemp（既存テストハーネス前提）

## 非機能要件（NFR）

- **パフォーマンス**: テスト追加のみ（実行時間影響は軽微）
- **セキュリティ**: 特になし
- **スケーラビリティ**: 特になし
- **可用性**: 既存テスト緑を維持

## 技術的考慮事項

- v3 cycle 解決入口は `state-read.sh` の `current_cycle` 読取。既存 `make_valid_state()` fixture を再利用
- git 履歴非依存は mktemp サンドボックス内で別 cycle 名の commit を作って検証
- 既存仕様が既に明示指定一本化のため、回帰テスト追加で挙動変更は発生しない想定（差分が出た場合は要調査）
