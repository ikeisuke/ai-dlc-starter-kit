# Unit: 禁止パースパターンの CI 機械検出（T4）

## 概要

個別 consumer スクリプトに frontmatter 構造解釈の禁止パターン（`grep`/`sed`/`awk`/permissive `jq`）が混入していないかを機械検出する独立スクリプトを追加し、GitHub Actions のジョブで実行する。Unit 001 で確立した共有 parser 境界からの逸脱（個別スクリプトでのローカルパース再実装）を、人手レビューに頼らず自動で弾く。

## 含まれるユーザーストーリー

- ストーリー 3: 禁止パースパターンの CI 機械検出（T4）

## 責務

- `skills/aidlc-v3/scripts/`（`lib/` と `tests/` を除く個別 consumer スクリプト）を走査し、**frontmatter 構造解釈の文脈に限定して**禁止パターンを検出する独立スクリプト（例: `scripts/check-frontmatter-parse-guard.sh`）の追加
- allowlist（`lib/` = 共有 parser 本体 / `tests/` = fixture）の除外
- 禁止 `jq` coerce（`// 既定値`・`?` 型エラー抑制・暗黙型変換）の検出は **frontmatter パース文脈** に限定する。`state-*.sh` の JSON / jq は正当な用途であり検出対象外（Intent 除外事項 = JSON 再設計しない / jq 一本化維持と整合）
- 終了コード規約（0=合格 / 1=違反 + 違反箇所報告 / 2=システムエラー）の遵守
- GitHub Actions ワークフローへのジョブ追加（PR で違反を fail させる）

## 境界

- **扱わない**: doctor コマンドの新設（未実装・予約 / Intent 除外事項）。検出は CI チェックとして実装する
- **扱わない**: 共有 parser ライブラリ本体の実装（Unit 001）
- **扱わない**: framework 側（`skills/aidlc/`）スクリプトの検出（対象は v3 本体 `skills/aidlc-v3/scripts/` のみ）
- **扱わない**: `state-*.sh` の JSON / jq パースの検出。JSON は jq 一本化が正当な設計（Intent 除外事項）であり、本検出は frontmatter 構造解釈に混入した禁止パターンのみを対象とする。`state-*.sh` を走査対象に含める場合でも、JSON 用途の jq は誤検出しない（検出は frontmatter 文脈に限定）

## 依存関係

### 依存する Unit

- Unit 001: 共有 frontmatter parser ライブラリ集約（依存理由: 検出スクリプトの allowlist が `lib/` の存在を前提とし、合格条件が「3 consumer が共有ライブラリへ移行済み」であるため、001 完了後でないと CI が安定して緑にならない）

### 外部依存

- bash、grep/sed/awk（検出ロジック実装）、GitHub Actions ランナー（jq/git）

## 非機能要件（NFR）

- **パフォーマンス**: CI ジョブとして許容範囲の実行時間（スクリプト走査は高速）
- **セキュリティ**: 特になし
- **スケーラビリティ**: 将来 consumer 追加時も走査対象に自動的に含まれる（ディレクトリベース走査）
- **可用性**: false positive を抑え、正当な共有 parser 利用をブロックしない

## 技術的考慮事項

- ドッグフーディング特殊処理を本体に埋めない原則: 検出スクリプトの存在を opt-in シグナルとして扱う
- コメント行・文字列リテラル内の誤検出を抑制する走査ロジック
- 検出パターンは Unit 001 で文書化された禁止規約と整合させる
