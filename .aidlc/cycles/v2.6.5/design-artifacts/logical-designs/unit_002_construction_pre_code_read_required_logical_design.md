### コンポーネント詳細

#### `steps/construction/02-design.md` のステップ 0 追加

- **責務**: 設計起草前の事前コード読込み工程を AI エージェントが実施するための SoT 手順
- **挿入位置**: 既存「**重要**: このフェーズでは設計ドキュメントのみ作成する...」記述の **後**、既存「## ステップ1: ドメインモデル設計」の **前**
- **構造**:

  ```text
  ## ステップ0: 事前コード読込み【必須 / depth_level != minimal の場合】

  **スキップ条件**: `depth_level == minimal` のときスキップ可（設計ステップ自体スキップ可と同条件）

  改修対象機能の既存実装コードを事前に Read し、ドメインモデル / 論理設計の冒頭に以下 3 観点を記述する。

  **失敗時**: 設計レビュー (`reviewing-construction-design`) の「### 設計プロセス」観点で「事前コード読込み不足」指摘 → 修正されるまで Round 反復
  ```

#### `reviewing-construction-design/SKILL.md` の「### 設計プロセス」セクション追加

- **責務**: 設計成果物の冒頭に事前コード読込みステップが記述され、(a)(b)(c) 3 観点に具体記述があるかを検証する観点
- **挿入位置**: 既存「### 依存関係」セクションの **後**、「## 共通基盤」の **前**
- **構造**:

  ```text

    - **失敗時**: 「事前コード読込み不足」指摘として Round 反復
  ```

## 処理フロー概要

### 設計起草 → 設計レビュー処理フロー（改修後）

**ステップ**:

1. `02-design.md` ステップ 0 でドメインモデル冒頭に事前コード読込みセクションを記述（`depth_level != minimal` 時必須）
2. `02-design.md` ステップ 1 でドメインモデル本体を設計
3. `02-design.md` ステップ 2 で論理設計
4. `02-design.md` ステップ 3 で設計レビュー（`reviewing-construction-design`）実施
5. レビューワーは「### 設計プロセス」観点で事前コード読込みセクション存在 / 内容充足を判定
6. 不足あり → Round 反復 / clean → セミオートゲート判定
